From trend analytics to narrative intelligence

Report of the architecture and methodology meeting. The central shift: Trend → Multiple Narratives → Narrative-level Analysis, instead of treating every post in a trend as one homogeneous dataset.

1Meeting objective

The meeting refined the technical architecture and analytical methodology, covering:

  • Cross-platform scraping and normalization
  • Trend detection and lifecycle analysis
  • Narrative discovery and classification
  • Narrative-level sentiment
  • Demographic and regional analysis
  • Network analysis
  • Hybrid deterministic/LLM reasoning using Jev
  • Handling previously unseen narratives
  • Ambiguity and hallucination control
  • Bot / coordinated-activity detection
  • Narrative clustering
  • Search and caching strategy
  • Report generation
  • Possible blockchain extensions
  • Division of implementation responsibilities
The system should identify the different narratives within a trend and analyze each narrative separately.

4Core analytical model

TREND
  ├── Narrative A ── Tweet 1, Tweet 2, Tweet 3
  ├── Narrative B ── Tweet 4, Tweet 5, Tweet 6
  └── Narrative C ── Tweet 7, Tweet 8, Tweet 9
A trend is not itself a narrative. A trend contains multiple narratives.

Example trend #LPUProtest could contain:

Narrative A

An incident occurred and requires investigation.

Narrative B

The circulating claims are rumors and lack verified information.

Narrative C

The incident is being framed as a political stunt.

These are analytical categories derived from the discussed content, not conclusions the system should endorse.

5–8Narrative formation: hybrid Jev + LLM

The problem. When a new trend appears, the narrative pool is empty, so there is nothing to classify incoming posts into. The proposed solution is a hybrid Jev + LLM architecture.

Stage 1 — Jev classification

A batch (about 30 tweets) is compared against the known narrative pool. If it clearly matches an existing narrative, Jev assigns it.

Stage 2 — No suitable narrative

If Jev returns "none of the above" or null, the batch goes to an LLM / reasoning model, which generates a narrative and adds it to the pool. Future posts classify against it.

PostsJevNo suitable narrativeLLMGenerate narrativeAdd to pool

Example

Incoming: "LPU administration should answer for this incident." / "The university needs to be held accountable." / "Administration must explain what happened."

LLM-formed narrative: "LPU administration should be held responsible/accountable for the incident."

The narrative pool evolves

EmptyA, B, CA, B, C, D, E…

The pool lets the system adapt to narratives unknown when the trend first appeared.

Batch-based processing

The classification unit is about 30 posts. Each batch (1, 2, 3…) goes through Jev for narrative classification. Advantages:

  • Jev receives more contextual information.
  • Expensive reasoning is not run independently for every post.

9–10Interpreting Jev confidence, and assigning posts

With 45 narratives, Jev might return: A → 0.60, B → 0.20, X → 0.10, Y → 0.05 …

Not a probability distribution. Narrative X → 10% does not mean 10% of tweets belong to X. It may mean Jev sees some semantic compatibility between X and the batch.
Confidence / compatibility score ≠ percentage of posts in a narrative. This matters for backend data modeling and frontend visualization.

Desired output: Post → Narrative

Example: Tweet A → Narrative 1, Tweet B → Narrative 1, Tweet C → Narrative 2, Tweet D → Narrative 3. Batch-level Jev analysis assists classification, but storage must preserve the actual post-to-narrative relationship. That answers "Which posts support or discuss this narrative?" rather than only "Which narratives are present in this batch?"

13–15Summaries, clustering and discovery

Two types of summaries

Trend summary

  • What is happening?
  • How rapidly is it growing?
  • Where is it occurring?
  • Which platforms are involved?
  • How large is the conversation?

Narrative summary

  • What does it claim or discuss?
  • Which posts belong to it?
  • How much discussion surrounds it?
  • What sentiment is associated?
  • Who is propagating it?
  • How is it evolving?

The separation stops the trend summary from hiding disagreements or competing narratives.

Narrative clustering

Once enough narratives exist, semantically similar ones are grouped (for example 45 narratives → narrative groups).

Narrative Group: University Accountability
 ├── LPU administration should be responsible
 ├── Administration must answer
 ├── University failed to act
 └── Officials should explain the incident

A researcher searching "College Administration" can discover the related group. This keeps the dashboard from being overloaded with dozens of near-duplicate narratives.

Inferred demographics must be clearly distinguished from directly provided ones and never presented as verified facts.

20–22Network analysis and coordination detection

Network analysis

Core pipeline component. Models relationships such as User A → B → C → D, and broader structures: Users → Posts → Mentions / Replies / Shares → Network graph. Can be correlated with trend velocity and narrative propagation.

Bot / coordinated-activity detection (proposed add-on)

Option 1 — String similarity

Compare the current post with historical posts; high similarity suggests potential coordination.

Option 2 — Recent batch similarity

Cache the relevant posts from the previous five batches and compare the current batch. Near-identical variants such as "Justice for X", "Justice 4 X", "We need justice for X", "Justice must be given to X", combined with synchronized timing, are a signal.

Option 3 — Popularity / velocity

Is the engagement plausible? Example: 100,000 interactions in 20 minutes, checked against account history, reach, typical engagement, trend velocity and cross-platform activity.

String similarityTemporal similarityPopularity anomalyTrend velocityCoordination signal
This is a signal, not definitive proof that accounts are bots.

23–25Search-term extraction and ambiguity

#JusticeForUpendra naively tokenizes to Justice / For / Upendra. The system should isolate the meaningful entity with a higher relevance score:

TokenRelevance
Justice0.01
For0.04
Upendra0.98

Contextual disambiguation

Simple tokenization fails on ambiguous cases like #TheRapistUpendra, which can be misread without understanding the linguistic structure. Ambiguous cases go to a reasoning model that uses context and, where appropriate, external information.

HashtagLexical parsingAmbiguity detectedReasoning modelContextual interpretationSearch queryGoogle Trends / external data

This builds a meaningful query instead of searching every token blindly.

Context saving

Avoid repeatedly sending large context packages to reasoning models. Provide the original post plus the necessary contextual references (Tweet/Post → Reasoning model → Contextual interpretation), reducing cost and latency.

26Hallucination as a core risk

The architecture separates deterministic / structured classification from generative narrative formation.

Jev: can an existing narrative explain this?Yes → assignNo / null → LLM → candidate narrative → pool

This stops the LLM from generating a new narrative for every batch and reduces uncontrolled narrative proliferation.

27Data modeling principle

Trend

The broad topic being discussed.

Narrative

A particular interpretation, claim, framing or storyline within a trend.

Post

The underlying evidence / content.

Classification

The relationship between a post and a narrative.

A normalized design must not treat Narrative = Trend, because one trend holds many narratives.

37Major technical decisions

Narrative is the central unit

Trend → Narratives → Posts, not Trend → Posts.

Jev classifies known narratives

LLM discovers new narratives

Used when no suitable narrative exists.

Sentiment per narrative

Not one score for the whole trend.

Confidence ≠ probability

Not automatically a probability distribution.

Narrative groups

A higher-level abstraction over individual narratives.

Contextual reasoning

Ambiguous search terms require it.

Multi-signal bot detection

Combine signals, not one heuristic.

Redis vs PostgreSQL

Redis for transient, high-frequency state; PostgreSQL for persistent analytics.

Show the hierarchy

The frontend should expose it clearly.

40Final meeting outcome

The project moves from conventional social-media trend analytics to a narrative-centric, cross-platform intelligence architecture.

Sources → Posts → Trends → Narratives → Narrative Groups
  → Sentiment / Network / Demographics / Regional Signals
  → Lifecycle & Forecasting → Research Dashboard + Reports

The key innovation is hybrid narrative formation: the system can start with no predefined narratives, discover new ones when needed, and classify future content against the accumulated pool.

The project moves beyond "What is trending?" to: What narratives are forming around a trend, how are they evolving, who is participating, what sentiment surrounds each, where are they concentrated, and how is the conversation changing over time?

Immediate workstreams: backend narrative infrastructure, frontend narrative visualization, automated reporting, and research validation.
